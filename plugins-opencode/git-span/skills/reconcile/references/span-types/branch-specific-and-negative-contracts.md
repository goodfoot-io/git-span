# Branch-specific and negative contracts

Scope: reassess an existing span before refreshing it using branch-specific and negative contracts.

## When to use this type

A branch requires a field, action or state change to be absent. Anchor positive code capable of violating the prohibition; ordinary anchors do not hash absence itself.

## Information and anchors

State the branch condition and observations or effects that must be omitted; distinguish absence from null, false and an empty container.

Candidate anchor roles: branch guard; response constructor or effect-capable call; authoritative condition table; contrasting branch example. Select existing content carrying the rule or likely to be encountered at the risky decision. These are roles, not a required anchor count.

## Reassess and reconcile

1. Use the current why, anchor bytes and history from stage 3 of [the procedure](../procedure.md). Check shared finalizers, unconditional response fields and bypass calls that can introduce the forbidden observation.
2. Confirm authority and meaning before refreshing content. Preserve unresolved disagreements; return behavior findings to the owner.
3. Select evidence appropriate to the semantic change: Exercise both branches and inspect field presence and effects; rejection must not send a request or persist state when that is the promise.
4. Refresh unchanged identities or atomically replace moved paths/ranges under the procedure. Revise the why when its rule or scope changes; extend, split or consolidate only when the information requires it.
5. Retain useful explanation even when tested or reduced to one anchor. Retire only when the relationship/reminder is obsolete or adds no useful decision context. Require scoped zero drift; delegated work stays unstaged for the owner.

## Illustrative why

> A pending archive omits artifact_uri because no artifact exists; only the completed branch supplies it.

This example supplies no authority for another repository. Substitute its actual contract and scope; quote decisive requirement wording where available.
