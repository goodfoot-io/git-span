# Dimensional and conservation invariants

Scope: reassess an existing span before refreshing it using dimensional and conservation invariants.

## When to use this type

A calculation depends on units, classification, rounding boundaries or a balance across operations. State waste, fees, yields or other exceptions rather than inventing a neat but false conservation law.

## Information and anchors

State the equation, quantity units, input authority, rounding stage and accounted exceptions over the relevant scope.

Candidate anchor roles: domain units/classification table; conversion or planning formula; allocation ledger; feasibility/reporting consumer. Select existing content carrying the rule or likely to be encountered at the risky decision. These are roles, not a required anchor count.

## Reassess and reconcile

1. Use the current why, anchor bytes and history from stage 3 of [the procedure](../procedure.md). Check classifier inputs, unit conversions and rounding before changing the final formula; compare feasibility with the reported plan.
2. Confirm authority and meaning before refreshing content. Preserve unresolved disagreements; return behavior findings to the owner.
3. Select evidence appropriate to the semantic change: Use a partial-batch or boundary quantity and reconcile the balance; distinguish rounding each item from rounding the total.
4. Refresh unchanged identities or atomically replace moved paths/ranges under the procedure. Revise the why when its rule or scope changes; extend, split or consolidate only when the information requires it.
5. Retain useful explanation even when tested or reduced to one anchor. Retire only when the relationship/reminder is obsolete or adds no useful decision context. Require scoped zero drift; delegated work stays unstaged for the owner.
