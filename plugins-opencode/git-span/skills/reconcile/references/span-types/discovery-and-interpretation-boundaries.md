# Discovery and interpretation boundaries

Scope: reassess an existing span before refreshing it using discovery and interpretation boundaries.

## When to use this type

Finding a candidate does not establish eligibility for strict interpretation or execution. Explicit inputs may legitimately follow stricter rules than discovered neighbors; preserve authorised differences.

## Information and anchors

State discovery scope, ownership predicate, strict validation boundary, ignore/error policy and exactly-once identity where relevant.

Candidate anchor roles: discovery promise; traversal/expansion; eligibility predicate; strict parser; mixed-content specimen. Select existing content carrying the rule or likely to be encountered at the risky decision. These are roles, not a required anchor count.

## Reassess and reconcile

1. Use the current why, anchor bytes and history from stage 3 of [the procedure](../procedure.md). Check whether broader scanning became broader interpretation or permissive filtering now swallows malformed selected content.
2. Confirm authority and meaning before refreshing content. Preserve unresolved disagreements; return behavior findings to the owner.
3. Select evidence appropriate to the semantic change: Combine a valid target, unrelated neighbor and malformed eligible target; check inclusion and deduplication using the actual identity rule.
4. Refresh unchanged identities or atomically replace moved paths/ranges under the procedure. Revise the why when its rule or scope changes; extend, split or consolidate only when the information requires it.
5. Retain useful explanation even when tested or reduced to one anchor. Retire only when the relationship/reminder is obsolete or adds no useful decision context. Require scoped zero drift; delegated work stays unstaged for the owner.
