# Diagnostic evidence and causal localization

Scope: reassess an existing span before refreshing it using diagnostic evidence and causal localization.

## When to use this type

An opaque symptom admits multiple causes and evidence must cross a boundary to choose a repair. Bound and sanitize diagnostics; a repaired shared prerequisite permits downstream execution without proving its correctness.

## Information and anchors

Name candidate causes, evidence origin, fields/channel retained, correlation identity and the conclusions each observation supports.

Candidate anchor roles: evidence-producing stage; lossy wrapper; diagnostic schema/consumer; bounded worked decomposition. Select existing content carrying the rule or likely to be encountered at the risky decision. These are roles, not a required anchor count.

## Reassess and reconcile

1. Use the current why, anchor bytes and history from stage 3 of [the procedure](../procedure.md). Check whether wrappers discard stage evidence, new diagnostics violate a public channel contract, or a timeout is being mistaken for a cause.
2. Confirm authority and meaning before refreshing content. Preserve unresolved disagreements; return behavior findings to the owner.
3. Select evidence appropriate to the semantic change: Distinguish compile, launch, runtime and decode failure, or decompose a numerical discrepancy before changing the aggregate formula.
4. Refresh unchanged identities or atomically replace moved paths/ranges under the procedure. Revise the why when its rule or scope changes; extend, split or consolidate only when the information requires it.
5. Retain useful explanation even when tested or reduced to one anchor. Retire only when the relationship/reminder is obsolete or adds no useful decision context. Require scoped zero drift; delegated work stays unstaged for the owner.

## Illustrative why

> Compiler failures retain stage, status and captured stderr through the runner envelope; solution stdout remains separate from machine results.
