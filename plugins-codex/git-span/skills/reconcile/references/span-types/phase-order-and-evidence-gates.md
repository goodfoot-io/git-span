# Phase ordering and evidence gates

Scope: reassess an existing span before refreshing it using phase ordering and evidence gates.

## When to use this type

A check, decision or effect is valid only after information or evidence becomes available. A stated gate is context, not an executable guard; independent stages need no invented total order.

## Information and anchors

Name the prerequisite, dependent decision, necessary partial order and authority for the gate; separate runtime readiness from permission to change policy.

Candidate anchor roles: producer of facts; binder/merger or probe; ordering boundary; first dependent check or effect. Select existing content carrying the rule or likely to be encountered at the risky decision. These are roles, not a required anchor count.

## Reassess and reconcile

1. Use the current why, anchor bytes and history from stage 3 of [the procedure](../procedure.md). Check whether a moved validator now runs before binding, merging or probing, or after the first protected effect.
2. Confirm authority and meaning before refreshing content. Preserve unresolved disagreements; return behavior findings to the owner.
3. Select evidence appropriate to the semantic change: Contrast declaration with bound invocation, or unmet with satisfied prerequisites; verify no dependent effect occurs prematurely.
4. Refresh unchanged identities or atomically replace moved paths/ranges under the procedure. Revise the why when its rule or scope changes; extend, split or consolidate only when the information requires it.
5. Retain useful explanation even when tested or reduced to one anchor. Retire only when the relationship/reminder is obsolete or adds no useful decision context. Require scoped zero drift; delegated work stays unstaged for the owner.
