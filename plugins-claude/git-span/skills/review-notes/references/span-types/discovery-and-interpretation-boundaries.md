# Discovery and interpretation boundaries

Scope: find and declare spans during behavioral review using discovery and interpretation boundaries.

## When to use this type

Finding a candidate does not establish eligibility for strict interpretation or execution. Explicit inputs may legitimately follow stricter rules than discovered neighbors; preserve authorised differences.

## Information and anchors

State discovery scope, ownership predicate, strict validation boundary, ignore/error policy and exactly-once identity where relevant.

Candidate anchor roles: discovery promise; traversal/expansion; eligibility predicate; strict parser; mixed-content specimen. Select existing content carrying the rule or likely to be encountered at the risky decision. These are roles, not a required anchor count.

## Review and add

1. Begin with the reviewed change and affected consumer: Check whether broader scanning became broader interpretation or permissive filtering now swallows malformed selected content.
2. Establish the rule independently of the changed implementation. Distinguish a defect, an authorised change and an unresolved requirement before editing metadata.
3. Obtain or propose applicable distinguishing evidence: Combine a valid target, unrelated neighbor and malformed eligible target; check inclusion and deduplication using the actual identity rule.
4. Inspect existing spans at the changed site and participating locations. Extend a useful existing span; otherwise propose a new span carrying this rule and scope, then follow step 5b in [the skill](../../SKILL.md). A useful single-anchor reminder is eligible.
5. Report the changed decision, evidence limits and unresolved finding to the parent. Leave span edits unstaged; the parent owns production edits, validation and commits.
