# rkyv-upgrade-fixture — legacy catalog blobs + golden outputs

Static fixtures proving the migration tool decodes legacy ref-backed catalogs
(`refs/spans/v1/catalog` tree of `*.span` rkyv-0.8 blobs) identically across the
rkyv-js upgrade (patched GitHub snapshot `2c3fc14` → npm 0.3.0), and a permanent
byte-stability gate for every later change to [../span-ref-to-tracked-file.mjs](../span-ref-to-tracked-file.mjs).

Layout:

- `blobs/*.bin` — four full catalog blobs (8-byte header `[FORMAT_VERSION=0, 0u8;7]` + rkyv payload).
- `expected/*.json` — decoded logical values of each blob (bigints as `"…n"` strings), generated by decoding with rkyv-js 0.3.0 and cross-checked against the pinned snapshot.
- `content/*.txt` — anchor content bytes; their git blob OIDs (sha1, content-addressed, therefore stable across machines) are embedded in the catalog blobs' `blob` fields.
- `golden/stdout.txt`, `golden/stderr.txt` — captured dry-run output of the **pre-upgrade** bundle over the assembled scratch repo; [../check-migration-golden.mjs](../check-migration-golden.mjs) enforces byte equality against whatever bundle is currently built.

Provenance: blobs were generated by a throwaway Rust program replicating
`packages/git-mesh/src/mesh/archive.rs` at commit ce4060e exactly (`#[derive(Archive,
Serialize, Deserialize)]` types, `rkyv::to_bytes::<rancor::Error>`, same header logic),
i.e. the same serializer that wrote real legacy catalogs. Before committing, all four
payloads were decoded by BOTH the pinned snapshot sources and npm rkyv-js@0.3.0:
values agreed and decode→re-encode was byte-identical to the Rust bytes for both
libraries — the evidence that makes strict golden equality a sound post-upgrade bar.
(Research note: card repo `notes/golden-fixture-spike.md`.)

Regeneration (exceptional — these are static assets):

1. Rebuild the generator from archive.rs @ ce4060e; embed fresh content OIDs if
   `content/*.txt` changed (`git hash-object` reproduces OIDs from those exact bytes).
2. Regenerate `blobs/*.bin`, re-run both-library decode agreement, refresh `expected/*.json`.
3. Recapture goldens ONLY from the pre-change bundle (`node scripts/check-migration-golden.mjs --update`)
   and record why in the change description.
